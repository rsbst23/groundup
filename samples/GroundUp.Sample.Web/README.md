# GroundUp Sample Web App

A browser app for calling and testing the GroundUp sample API (`samples/GroundUp.Sample`). It is a test tool first: plain MUI forms and tables. It may later become the template that GroundUp applications copy, so its structure and conventions are meant to be copied.

Stack: React, Vite, TypeScript (strict), MUI, TanStack Query, TanStack Router (file-based routes), zod, Vitest. Node 22 (`.nvmrc`).

Development only. It is not part of `groundup.sln` and is never packed.

## Run it

1. Start Docker (Postgres and Keycloak) from the repo root:
   ```powershell
   docker compose -f docker-compose.yml -f docker-compose.keycloak.yml up -d
   ```
2. In Kiro, pick **API + Web app** in the Run and Debug dropdown and press F5. That starts the sample API on port 5000, runs `npm install`, starts this app on port 5173 and opens the browser.

   Or by hand: start the sample API (F5 with ".NET Core Launch (web)", or `dotnet run --project samples/GroundUp.Sample`), then in this folder:
   ```powershell
   npm install
   npm run dev
   ```
3. Open http://localhost:5173.

Keycloak must allow port 5173: see "Before You Start" in [TESTING.md](TESTING.md).

The API's address comes from `GROUNDUP_API_URL` (default `http://localhost:5000`); copy `.env.example` to `.env` to change it.

| Script | What it does |

| `npm run build` | Type check (`tsc -b`) and production build |

| `npm run test:watch` | Vitest in watch mode |

## How it talks to the API

The browser only talks to the dev server. The dev server proxies `/api`, `/auth`, `/setup`, `/health` and `/swagger` to the sample API and keeps the browser's Host header. So the API builds the Keycloak `redirect_uri` and the post-logout address on port 5173, and sets its cookies there: cookies, SameSite and CSRF behave as they would for a deployed client. The proxied prefixes are listed once, in `src/proxiedPrefixes.ts`.

## Folder layout

```
src/
  main.tsx, router.ts, queryClient.ts, theme.ts   app setup
  proxiedPrefixes.ts                             paths sent to the API
  routes/          one file per page (file-based routing); __root.tsx is the layout
  routeTree.gen.ts generated by the router plugin, committed, never edited
  api/             the API client and endpoint functions
    client.ts      apiFetch: the one way to call the API
    csrf.ts        the in-memory CSRF token
    errors.ts      ApiError and how each error shape is read
    inspector.ts   the request history behind the Requests panel
    auth.ts, ...   endpoint functions, one file per API area
    types.ts       DTO types (written by hand for now)
  components/      shared components (layout, error panel, session banner, inspector)
  features/<area>/ an area's queries, mutations and components; route files stay thin
  features/access/ permission checks (can, PermissionButton), RequireTenant and RequirePermission
  features/list/   ListTable and the list view in the URL (page, sort, search, status)
  features/common/ shared pieces (dates, ConfirmDialog, RoleSelect)
```

Tests sit next to the code as `*.test.ts`; `src/api/testing.ts` has the fetch mock.

## Rules

- **Pages never call `fetch`.** They call endpoint functions in `src/api/` through TanStack Query (`useQuery`, `useMutation`), which go through `apiFetch`.
- **Errors are shown with `ErrorPanel`.** It shows the status, message, error code, details and correlation ID for any failed call.
- **No app route may start with a proxied prefix** (`/api`, `/auth`, `/setup`, `/health`, `/swagger`, also as a plain prefix, so not `/authors` either), or the dev server sends the page to the API. That is why the setup page is `/wizard`. `src/routes/routes.test.ts` fails on a clash.
- **New API paths** the app calls must have their prefix in `src/proxiedPrefixes.ts`.
- **Search parameters are typed.** A route that reads the query string declares a zod schema in `validateSearch`.
- **After anything that changes the user or the tenant** (set tenant, sign out, leave, create organization, refresh), call `onSessionChanged(queryClient)`. It drops the CSRF token, which is tied to the user, and refreshes the session.
- **CSRF is automatic.** `apiFetch` fetches `GET /auth/csrf` before the first POST, PUT, PATCH or DELETE, keeps it in memory only and retries once after `403 CSRF_VALIDATION_FAILED`. When nobody is signed in it sends no token, which the API accepts. Signing in is a full-page redirect, which reloads the app and empties memory; a client-side sign-in would have to call `clearCsrfToken()`.
- **Nothing secret is stored.** The Requests panel masks `Authorization`, `Cookie`, `Set-Cookie` and `X-CSRF-Token`, and body fields whose names contain token, password or secret, before recording. A page that must show a value once (a new join link) shows it on the page.
- **API data lives in TanStack Query.** Query keys start with the area (`['members', tenantId, view]`); after a change, invalidate the area's key and every page showing it reloads. After a delete, first take the row out of the cached pages (`withoutPageItems` in `features/list/cachedPages.ts`), so it disappears at once rather than after the reload. Keys of tenant data include the tenant id.
- **Client-only state shared across pages** (not from the API) goes in a Zustand store when it is needed. None is needed yet; the organization picker's open flag is a tiny store in `features/session/pickerRequest.ts`.
- **Actions follow the session's permissions.** Use `PermissionButton` / `PermissionIconButton` (`features/access`) with the permission the API checks: the button is disabled, with a tooltip naming the permission, when `/auth/me` does not list it. The API still checks every request.
- **Every admin page wraps its content in `RequirePermission`** (inside `RequireTenant`) with the key its list endpoint needs. Without it the page says "You need the permission … to see this page" and calls nothing. A 403 that still arrives (`PERMISSION_REQUIRED`, `ROLE_REQUIRED`) is shown by `ErrorPanel` with the missing permission or role.
- **Lists use `ListTable`** with the view in the URL: the route sets `validateSearch: listSearchSchema`, the page uses `useListView` and `usePageBack`, and only columns the API can sort (its field names) get a `sortField`. Sorting, search and filtering run on the server.
- **A new route file** needs `npx vite build` once (the router plugin regenerates `routeTree.gen.ts`) before `npm run build`, whose type check runs first.
- **Each page story adds its part to [TESTING.md](TESTING.md).**

## Versions

Exact versions are pinned in `package.json`. TypeScript is 6.0.3 rather than 7 because typescript-eslint 8.74 supports TypeScript below 6.1 only; move to 7 when it does.
